## 一、v2.5 scores 接入修复（08:33~09:03）

### 根因分析

**Bug 在 `task3_v21_backtest.py` 的 `load_scores_parquet()` 函数中：**

scores.parquet 的 ts_code 字段为 Tushare 格式（`000001.SZ`），但原转换逻辑只是简单在左侧加前缀：
```python
code_str = f"sz.{code_str}"  # → "sz.000001.SZ"（错误！）
```
正确 Qlib 格式应为 `sz.000001`。

**v2.1 的 "used=328" 是假象：**
- `get_fund_score_v21` 在未命中时返回 `FUND_DEFAULT_SCORE`（50），从不返回 None
- 调用方 `if fund_score is None` 永远为 False → `default` 计数器从未触发
- 所有交易都被计入 `used`，造成"使用了真实评分"的假象

### 修复内容

| 文件 | 改动 |
|------|------|
| `task3_v21_backtest.py:load_scores_parquet()` | 提取纯数字部分后再加前缀（`000001.SZ`→`000001`→`sz.000001`） |
| `task7_v25_backtest.py:get_fund_score()` | 优化查询用 reversed 排序，效率更高 |

### 验证结果

```python
scores: {'used': 302, 'default': 0, 'rejected': 59, 'passed': 243}
```
- **302 笔**信号命中真实评分 ✅
- **0 笔**默认 50 分 ✅
- **59 笔**因 < FUND_SCORE_MIN(30) 被拒绝

### 回测结果

| 指标 | v2.5 (修复后) | v2.3 (默认50) | 对比 |
|:----|:-----------:|:------------:|:---:|
| 总收益 | 21.95% | 23.70% | ↓ |
| 夏普 | **0.062** | **0.11** | ↓ |
| 最大回撤 | -10.33% | ≈-11% | 基本持平 |
| 胜率 | 44.5% | 45.8% | ↓ |
| 盈亏比 | 1.99 | 1.85 | ↑ |
| 交易 | 238笔 | 249笔 | ↓（评分过滤） |

### 结论

**✅ 修复成功** — scores 确实接入了
**❌ 绩效未提升** — 真实评分入场前过滤（<30拒绝）后夏普反从 0.11 降至 **0.062**
**判定：当前框架上限已到**（修复后夏普 < 0.10），按原计划推进长期任务
