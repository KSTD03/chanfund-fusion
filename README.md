## 项目概述

ChanFund Fusion 是一个基于 **缠论（Chan Theory）技术分析** 与 **基本面多因子评分** 双系统融合的 A 股量化选股策略。

### 核心理念

1. **技术面找买点** — 利用缠论结构（笔、中枢、背驰、三类买卖点）识别技术买卖信号
2. **基本面筛好股** — 通过多因子模型计算股票基本面综合得分，过滤劣质标的
3. **融合仲裁** — 技术信号 + 基本面得分共同决定最终开仓决策，信号有分级、有过滤
4. **动态风控** — 保护性移动止损、ER噪声过滤、冷却期机制、红黄牌排雷、分级仓位系数

### 实现特点

- **增量计算**：每日只处理新 K 线，无需全量重算
- **事件驱动**：缠论计算输出结构化事件（分型确认、笔确认、中枢更新、信号生成）
- **信号生命周期**：PENDING → CONFIRMED → EXECUTED / INVALIDATED / EXPIRED
- **回测兼容**：基于 Qlib `BaseStrategy` 接口，可直接用 Qlib 回测引擎运行

## 核心策略逻辑

### 1. 技术子系统（缠论）

位于 `tech/` 目录，实现增量缠论结构计算。

#### 缠论数据结构

| 数据类 | 定义 | 作用 |
|--------|------|------|
| `FX` | 分型（顶/底分型） | 笔的构成单元 |
| `Bi` | 笔（向上/向下） | 基础价格走势单元，含振幅 |
| `ZS` | 中枢（ZG/ZD/GG/DD） | 盘整区间，判断三类买卖点 |
| `Divergence` | 背驰（硬/软） | 趋势衰竭信号 |
| `Signal` | 交易信号 | 策略最终输出 |

#### 增量状态机

每根新 K 线触发 5 个事件，严格按序处理：

```
事件1 — 更新：用新 K 线极值更新当前笔
事件2 — 检测：检测是否形成新潜在分型
事件3 — 确认：分型成立且反向 → 确认旧笔、开启新笔
事件4 — 中枢：基于已确认笔序列，检查中枢状态变化
事件5 — 信号：检查背驰或三类买卖点
```

#### 技术信号类型

| 信号类型 | 优先级 | 仓位系数 | 说明 |
|----------|--------|----------|------|
| `hard_divergence` | 最高 | 1.0 | 已确认硬背驰 + 趋势强劲 |
| `third_point_buy` | 高 | 0.8 | 三类买卖点 |
| `second_class_buy` | 中 | 0.7 | 二类买卖点 |
| `trend_follow` | 中 | 0.6 | 趋势跟随 |
| `soft_divergence` | 低 | 0.25 | 软背驰（试探仓） |

#### 试探仓机制

软背驰信号不走标准开仓流程，而是：
- 以标准仓位 25% 试仓
- 放宽止损至 1.5 倍
- 2R 目标：盈利 2 倍风险后平一半，剩下一半移损至成本
- 20 根 K 线未升级则清仓

#### ER 噪声过滤

使用 **效率比率（Efficiency Ratio, ER）** 评估当前价格运动的趋势/噪声水平：

| ER 分位 | 判定 | 操作 |
|---------|------|------|
| < 15% | 极端噪声 | 丢弃信号 |
| 15% ~ 25% | 中等噪声 | 降权 0.5 通过 |
| 25% ~ 80% | 正常 | 正常通过 |
| > 80% | 强趋势 | 增强系数 1.2 |

### 2. 基本面子系统

位于 `fund/` 目录，提供多因子评分和排雷检测。

#### 因子模型

- **实时因子**：每日更新（如动量、波动率等）
- **财报因子**：仅在披露日更新（PIT 数据管道防未来）
- **平滑过渡**：新财报前 10 个交易日新旧值加权混合

#### 评分流程

```
原始因子值 → MAD去极值 → 行业ZScore → 市值中性化 → 因子加权 → 融合得分(0-100)
```

#### 红黄牌排雷（RedFlagDetector）

| 牌级 | 触发条件 | 处理 |
|------|---------|------|
| 🔴 红牌 | ST、立案调查、审计否定意见 | 系数 0（禁止买入） |
| 🟡 黄牌 | 质押>50%、商誉>30%、应收/OCF/存货异常 | 系数 0.5（仓位减半） |

#### 宏观场景识别

周期检测器基于三个指标进行流程化判定：
1. 中证全指波动率（年化波动率及历史分位）
2. 信用利差 Z-Score
3. 价值动量 Z-Score

输出四种场景：**防御避险 → 质量成长 → 深度价值 → 均衡中性**

### 3. 融合引擎

位于 `fusion/` 目录，是信号仲裁的核心。

#### 融合分计算

```
Fused_Score = 0.6 × Tech_Score + 0.4 × Fund_Score
```

技术评分映射：hard_divergence=90, third_point_buy=80, soft_divergence=55

#### 信号过滤管线

每个信号通过以下 8 道过滤：

```
① ER 噪声过滤 → ② 趋势方向过滤 → ③ 红黄牌过滤
→ ④ 融合分检查 → ⑤ 冷却期检查 → ⑥ 跳空过滤
→ ⑦ 预算检查 → ⑧ 行业集中度检查
```

#### 仓位系数计算

```
最终仓位 = 信号仓位系数 × 噪声降权 × 趋势降权
           × 红黄牌系数 × 基本面信心 × 组合风险调节
```

### 4. 风控模块

位于 `risk/` 目录。

#### 动态风险预算

```
仓位(股数) = (总权益 × risk_per_trade%) / |入场价 - 止损价|
```

- 单笔风险：总权益的 1%
- 单只上限：8%
- 单行业上限：25%
- 日风险预算：总权益的 3%

#### 保护性移动止损

| 阶段 | 止损逻辑 |
|------|---------|
| 初始 | max(入场价 - ATR×2.0, 最近笔低点) |
| 持仓中 | 新高后上移至最近笔低点 |
| 中枢离开后 | 上移至中枢上沿 ZG |
| 盈利 > 5% | 保本移损（上移至成本） |
| 长持仓(>60天) | 宽止损 15% |
| 峰值回落 > 10% | 止盈清仓 |

#### 多级止盈

| 级别 | 触发 | 操作 |
|------|------|------|
| 第一止盈 | +6% | 减 30% |
| 第二止盈 | +13% | 减 50% |
| 峰值回落 | 从峰值回落 > 8% | 清仓 |

#### 冷却期机制

同一只股票连续 2 次止损 → 进入 10 个交易日冷却期。盈利平仓则重置计数器。

### 5. 信号过滤管线（完整流程图）

```
每日 generate_trade_decision()
  │
  ├─ ① 获取技术信号（已确认，T+1）
  ├─ ② 获取最新基本面得分
  ├─ ③ ER 噪声过滤（Phase 2）
  ├─ ④ 趋势方向过滤（Phase 4）
  ├─ ⑤ 红黄牌过滤（Phase 5）
  ├─ ⑥ 融合分检查
  ├─ ⑦ 冷却期检查
  ├─ ⑧ 跳空过滤
  ├─ ⑨ 预算检查
  ├─ ⑩ 行业集中度检查
  │
  ├─ 通过 → 动态仓位计算
  │         ├─ 信号分级仓位系数（Phase 3）
  │         ├─ 动态风险预算 = (权益×risk%)/|入场-止损|
  │         └─ 约束：单只上限8% / 行业上限25%
  │
  └─ 拒绝 → 记录拒绝原因（归因日志）

  ★ 每日结束后更新：
     - 保护性移动止损（缠论结构驱动）
     - 试探仓状态检查
     - 基本面恶化检查
```

## 回测框架

### 总体架构

基于 **Qlib** 回测框架，继承 `BaseStrategy` 实现每日 `generate_trade_decision` 回调。

### 回测运行器

- **`run_backtest_v101.py`** — 全量回测运行器
  - 股票池：全 A 股（~5157 只）
  - 回测区间：2021-01-01 ~ 2026-04-29（~5 年）
  - 预热：2018-01-01 ~ 2020-12-31（3 年）
  - 初始资金：1,000,000
  - 输出：Markdown 报告 + CSV 成交记录

### 数据流

```
Qlib CN Data (Parquet)
  └─ MarketDataProvider → K线数据
      ├─ TechSignalEngine → 缠论结构计算 → 技术信号
      ├─ FundFactorEngine → 基本面评分
      └─ PITDataPipeline  → 财报数据（防未来偏差）

技术信号 + 基本面评分 → FusionRules (过滤管线) → 决策列表
                                                    └─ PositionManager → 目标权重
```

### 分批次回测

5000+ 只股票的全量回测采用分批次加载策略：
- 批次大小：500 只/批
- 信号引擎状态和持仓跨批次保留
- 每批结束后释放行情数据，控制内存峰值 < 6GB
- 预计全量回测耗时：~21 分钟

### 内存优化

| 模块 | 预估占用 | 优化策略 |
|------|---------|---------|
| 行情数据 | 523 MB/批 | 分批次加载，批后释放 |
| 缠论结构 (chan_cache) | ~3.1 GB | 60 天 GC 清理无信号股票 |
| 交易日志 | ~15 MB | 流式写入磁盘 |
| 财务数据 | ~50 MB | 常驻内存 |

| 7 | 测试集验证 | 全量回测 | 测试集 |
| 8 | 鲁棒性验证 | 参数平面扫描 | 随机子集 |

### 数据切片

- **训练集**：60%（~2017-2021）
- **验证集**：20%（~2022-2023）
- **测试集**：20%（~2024-2026）

## 快速开始

### 环境要求

- Python 3.10+
- Qlib (Microsoft)
- Tushare Pro / Baostock（数据源）

### 安装

```bash
# 克隆仓库
git clone https://github.com/KSTD03/chanfund-fusion.git
cd chanfund-fusion

# 安装依赖
pip install qlib pandas numpy pyyaml psutil

# 配置 Tushare Token（如需增量数据）
export TUSHARE_TOKEN="your_token_here"
```

### 数据准备

```bash
# 下载 A 股日线数据到 Qlib 格式
python scripts/download_data.py

# 构建基本面评分（可选）
python factors/build_fundamental_scores.py
```

### 运行回测

```bash
# 全量回测（默认模式）
python run_backtest_v101.py

# 后台运行
nohup python run_backtest_v101.py > backtest.log 2>&1 &
```

### 参数优化

```bash
# 查看优化状态
python optimization/run_optimization.py --status

# 单步优化
python optimization/run_optimization.py --step 1

# 全步骤运行
python optimization/run_optimization.py --all
```

### 冒烟测试

```bash
python tests/smoke_test.py
python tests/run_baseline_test.py
```
